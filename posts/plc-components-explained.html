PLC Components Explained: What's Actually Inside the Controller

A PLC looks like one box, but it's really five distinct components — power supply, processor, input modules, output modules, and a communication module — wired together on a backplane and cycling through the same read-execute-write loop, thousands of times an hour. Here's what each part does.

One box, five distinct jobs

Open up a PLC rack and it's tempting to see one integrated unit. In practice it's a set of separate modules, each doing one job, plugged into a shared backplane that carries both power and data between them. The power supply and CPU keep the whole rack running and executing logic; the input and output modules are the only parts that ever touch field wiring; and the communication module is what lets the rest of the plant see what the PLC is doing.

That separation isn't incidental — it's the whole reason PLCs are as reliable and flexible as they are. The CPU that runs your logic is the same CPU whether you're reading two switches or two hundred; you simply add or remove I/O modules to match the application.

1Power Supply Module

  • Converts incoming AC (often 120/240V) or DC into the low-voltage DC the CPU and I/O modules need to operate
  • Sized off the total backplane current draw of every installed module — add modules and you can outgrow the supply
  • Powers the rack electronics only; field sensors and actuators almost always run off a separate 24V DC supply

2CPU / Processor Module

  • Executes the user's control program, held in memory alongside the operating system, timers, counters and data tables
  • Runs a continuous scan cycle: read every input, execute the logic against it, write the resulting outputs
  • Determinism comes from this fixed loop — the same inputs reliably produce the same outputs, scan after scan

3Input Modules

  • Discrete input modules read simple on/off signals — limit switches, push buttons, proximity sensors
  • Analog input modules read continuous signals like 4–20mA or 0–10V from transmitters and instruments
  • Both convert field-level electrical signals into digital values the CPU can actually work with, with opto-isolation protecting the CPU side

4Output Modules

  • Discrete output modules switch field devices on/off — relays, solenoids, motor starter coils
  • Analog output modules send 4–20mA or 0–10V control signals to valves, VFDs and other final control elements
  • Module type — relay, transistor, or triac — sets switching speed and which loads it can actually drive

5Communication Module

  • Links the PLC to HMI panels, SCADA systems, and other controllers over protocols like Modbus, Ethernet/IP or Profibus
  • Many CPUs include a built-in comm port; larger systems add dedicated modules for redundancy or protocol conversion
  • Handles data exchange as background housekeeping, so it doesn't slow down the CPU's core scan cycle

How the scan cycle actually runs

1Input scan — the CPU reads the state of every input module in one pass, capturing a snapshot of field conditions.
2Program scan — the CPU executes the user logic against that snapshot, rung by rung in ladder logic or line by line in structured text.
3Output scan — the CPU writes the resulting output states to the output modules in one pass, updating the field devices.
4Housekeeping — communication, diagnostics and any forced overrides are handled before the next cycle starts.
5The cycle repeats continuously, typically completing end-to-end in single-digit to low double-digit milliseconds.

Why inputs and outputs stay separate from the CPU

Field wiring is a hostile environment for sensitive electronics — voltage spikes, electrical noise, and wiring mistakes are routine. Input and output modules exist partly to keep that mess away from the processor: opto-isolation on most I/O modules electrically separates the field side from the backplane side, so a wiring fault or surge on a sensor circuit doesn't take down the CPU. The other reason is modularity — because I/O lives on its own modules, you can mix discrete and analog, add or remove points, and scale a rack up or down without ever touching the processor that runs your logic.

Why this architecture is common

Modularity
Isolation
Scalability

Splitting a PLC into power, processing, I/O and communication modules is what lets the same processor run a two-point machine or a two-thousand-point plant — you scale the rack, not the brain. It also isolates failure: a bad output module doesn't take the CPU offline, and a noisy field circuit doesn't corrupt the program in memory. That combination of scalability and fault isolation is a big part of why this architecture has stayed the default for industrial control for decades.

Key takeaways

  • ✓The CPU never touches field wiring directly — I/O modules act as the buffer and translator between it and the process.
  • ✓A power supply module's job is only to feed the backplane; field sensors and actuators typically run off a separate 24V supply.
  • ✓The scan cycle's read-execute-write structure is why PLC logic is deterministic and repeatable, unlike free-running software.
  • ✓Discrete and analog I/O modules aren't interchangeable — matching module type to signal type is a wiring-time decision, not a programming one.
  • ✓Communication modules are what turn a standalone controller into a networked one, without slowing down the scan.

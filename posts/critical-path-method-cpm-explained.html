Critical Path Method (CPM): The Chain That Sets Your Finish Date

Not every late task delays a project. Only the tasks sitting on the critical path do — and finding that path is what separates schedule management from just watching a Gantt chart.

Engineerz CorneRReference · Scheduling
01
The critical path is the longest chain of dependent tasks from project start to finish — not the chain with the most tasks in it.
02
Every task on that path has zero float: slip it by a day and the whole project finish date slips by a day.
03
Tasks off the critical path have float — room to slip a little without moving the finish date.
04
The critical path can change as the project runs — a delayed non-critical task can eat its float and become critical.

The idea in one line

Draw every task as a box, connect the boxes in the order one task depends on another, and the longest route through that network — measured in duration, not number of boxes — is the critical path. It sets the earliest possible finish date for the whole project, because nothing downstream of it can start before everything on that path is done.

Two passes through the network

CPM finds the critical path with two sweeps through the same diagram:

A task with float = 0 is on the critical path. Everything else has room to move.

Worked example

Five tasks: A feeds B and C in parallel, B feeds D, C feeds D, D feeds E, E feeds F.

Forward & backward pass

A (3 days)ES 0, EF 3 · Float 0
B (5 days)ES 3, EF 8 · Float 0
C (2 days)ES 3, EF 5 · Float 3
D (4 days)ES 8, EF 12 · Float 0
E (6 days)ES 12, EF 18 · Float 0

C finishes on day 5, but D can't start until B is also done on day 8 — so C has three days of slack before it starts holding up the schedule. The critical path is A → B → D → E, totalling 18 days. C is real work, on the schedule, with a real deadline — it just isn't what's setting the project finish date.

Why float, not task count, decides what to manage

A five-task chain can matter more than a fifteen-task one It's tempting to focus attention on whichever branch of the schedule looks busiest. But a branch with fifteen short tasks and generous float can absorb weeks of minor slippage without moving the finish date, while a five-task chain with zero float moves the finish date the moment any one task runs long. Float, not activity count, is what tells a scheduler where to actually spend attention.

The path isn't fixed for the life of the project

As tasks report progress, floats get recalculated. A non-critical task that was supposed to take 2 days can run 5, quietly burning through its float; once that float hits zero, that task — and everything downstream of it — joins the critical path. This is why CPM is a living calculation done at every schedule update, not a diagram drawn once at kickoff and left alone. A path that was critical in month one can stop being the tightest constraint by month three, and a path that had slack early on can become the new bottleneck.

Key takeaways

  • ✓The critical path is the longest duration route through the network, not the route with the most activities.
  • ✓Float = Latest Start − Earliest Start. Zero float means the task is critical; any slip pushes the finish date by the same amount.
  • ✓Non-critical tasks have float, but float is a budget that shrinks as those tasks run late — not a permanent cushion.
  • ✓Recalculate the critical path at every schedule update — it can shift as the project progresses, not just at planning.

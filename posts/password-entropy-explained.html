Password Entropy Explained: What Actually Makes a Password Hard to Crack

"P@ssw0rd!" looks complex to a human and falls in seconds to a cracking tool — entropy explains why length, not symbol variety, is what actually matters.

Entropy measures how many guesses a brute-force attack needs on average, expressed in bits — it is not the same thing as "looks complicated."
02
Every extra character multiplies the guess space; every extra symbol type only adds a little to the base of that multiplication.

A long passphrase of ordinary words can have more entropy than a short string stuffed with symbols and numbers.

Entropy assumes a random, unpredictable password — predictable patterns (keyboard walks, l33t substitutions, dictionary words) are cracked far faster than their raw entropy suggests.

What entropy is actually measuring

Password entropy is a measure of unpredictability, expressed in bits. Each bit doubles the number of guesses an attacker needs to try on average before finding the password by brute force. A password with 40 bits of entropy needs on the order of 240 guesses; one with 60 bits needs 260 — roughly a million times more. The number comes from how large the character set is and how many characters long the password is, assuming every character is chosen independently and at random from that set.

The formula

H  =  L  ×  log2(N)
H = entropy in bits · L = password length in characters · N = size of the character set the password draws from (26 for lowercase only, 62 for upper+lower+digits, 95 for the full printable ASCII set)

Length sits outside the logarithm, character-set size sits inside it — that's the whole reason length dominates. Adding one more character multiplies the total guess space by N every time. Adding one more symbol category to the allowed set only multiplies N itself by a modest factor, which then goes through a logarithm and shrinks further. A longer password with a smaller character set very often beats a shorter password with a larger one.

Why "P@ssw0rd!" is weaker than it looks

A 9-character password using upper, lower, digits and symbols has a character set of roughly 95, giving a theoretical entropy around 9 × log₂(95) ≈ 59 bits. That already sounds respectable — until the assumption of true randomness breaks down. "P@ssw0rd!" isn't randomly chosen from that set; it's a dictionary word with predictable substitutions (@ for a, 0 for o) that cracking tools check specifically because so many real passwords follow that exact pattern. Its effective entropy against a real attacker is far below its theoretical maximum.

Theoretical entropyAssumes every character was chosen uniformly at random from the full allowed set — the textbook upper bound.
Effective entropyWhat's left once predictable patterns, dictionary words, and common substitutions are accounted for — usually much lower for human-chosen passwords.

Why long passphrases win

A four-word passphrase like "correct horse battery staple" is 28 characters drawn from a small set (lowercase letters plus spaces, N ≈ 27), giving roughly 28 × log₂(27) ≈ 133 bits if the words were truly randomly picked from a large dictionary — in practice closer to the entropy of the word choices themselves (about 11 bits per word from a 2,048-word list, so four words ≈ 44 bits, still comparable to or better than a short complex string, and vastly easier for a human to remember and type correctly). The general principle holds either way: length multiplies the search space directly, so a longer password build from a modest set of building blocks usually outperforms a short one stuffed with symbol variety.

Key takeaways

  • ✓Entropy in bits measures guess-space size, not visual complexity — length matters more than symbol variety because it multiplies the space directly.
  • ✓H = L × log₂(N): length sits outside the logarithm, character-set size sits inside it.
  • ✓Theoretical entropy assumes true randomness — predictable human patterns give attackers a shortcut that real cracking tools already exploit.
  • ✓A long, memorable passphrase from a small character set often beats a short, symbol-heavy password in both entropy and usability.

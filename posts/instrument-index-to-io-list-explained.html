From Instrument Index to I/O List: Counting Points and Sizing Cards

The instrument index lists every device and the I/O list turns it into signals and cards. Here is how tags read, how to count points by type, why each type rounds up separately and what a count leaves out.

Every transmitter, switch and control valve on a plant needs a tag, a data sheet and a place to land on the control system. The instrument index is the register that holds them, and the I/O list is what falls out of it when each instrument is mapped to the signals the control system has to handle. The point of the second list is to size the hardware: how many input and output cards, and how many of each kind.

Reading an instrument tag

Tags commonly follow the ISA 5.1 pattern, where the first letter gives the measured variable and the following letters give the function. Instruments that work together share a loop number, which ties the P&ID, the loop drawing and the I/O list together. For the symbols and layout, see P&ID instrument bubbles and tag anatomy.

TagReads as
FT-101Flow transmitter, loop 101
PT-205Pressure transmitter, loop 205
LT-310Level transmitter, loop 310
TIC-402Temperature indicating controller, loop 402
LSHH-310Level switch, high-high, loop 310

Counting I/O points

Each connection to the control system uses one point of a given type. These patterns are common, but the control philosophy and the vendor's wiring requirements decide each case.

  • Analog input (AI): a 4-20 mA transmitter, such as flow, pressure or level. See 4-20 mA current loop basics.
  • Analog output (AO): a control valve positioner or VFD speed reference, and sometimes an AI for position feedback.
  • Discrete input (DI): a switch, pushbutton, limit switch or motor run or fault feedback.
  • Discrete output (DO): a motor start command, solenoid or alarm beacon.

An on/off valve with two limit switches typically needs one DO and two DI. A motor starter often needs a start DO plus run and fault DI.

From points to cards

I/O cards are type-specific, so each signal type is rounded up to whole cards separately. With 16 points per card, 20 AI and 10 DI need 2 + 1 = 3 cards, even though 30 points divided by 16 would suggest 2. Add spare capacity on top, because projects reserve spare points for later additions. The percentage comes from the owner's or contractor's standard, so use your project's figure, for example 20%: 20 AI plus 20% is 24 points, which needs 2 cards at 16 per card and still leaves room. The instrument index and I/O list builder does the count by type and shows the cards needed, and it does not add spare for you.

What the count leaves out

  • Safety I/O. Safety-rated signals are normally kept on separate cards from standard I/O. See functional safety and SIL explained.
  • Fieldbus and serial devices. These are counted as communication links, not hard-wired points. See Modbus vs Profibus vs fieldbus.
  • Barriers, relays and marshalling. Intrinsically safe loops and interposing relays add hardware that does not appear in the I/O count.

To pick the instrument itself, use the instrument selector, and for signal ranges, the signal scaling tool. The index is a living document, so revise it whenever the P&IDs change.

Key takeaways

  • ✓Build the I/O list from the instrument index so the two never disagree.
  • ✓Count points by signal type, then round each type up to whole cards.
  • ✓Apply the project spare allowance after counting, since the builder does not add it.
  • ✓Treat safety I/O and fieldbus devices separately from the hard-wired count.

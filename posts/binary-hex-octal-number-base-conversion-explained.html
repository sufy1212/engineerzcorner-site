Binary, Hex & Octal Explained

Decimal, binary, octal and hex all count the same way — a digit runs out and a new column opens. What changes between them is only how fast that happens.

What a base actually is

A number base is simply how many distinct digits are available before a column runs out and forces a carry into the next one. Decimal (base 10) uses ten digits, 0–9, and carries once a column would need a "10." Binary (base 2) has only two digits, 0 and 1, so it carries at every single step — that's why binary numbers look so much longer than their decimal equivalents for the same value. Octal (base 8) and hexadecimal (base 16) sit on either side of binary as more compact ways of writing the exact same underlying value, using 8 and 16 digits respectively — hex borrows A–F for the digits beyond 9.

None of this changes what the number is. Decimal 13, binary 1101, and hex D are three different labels for the identical quantity — the same way "13," "thirteen," and "XIII" all name the same count without changing it.

The formulas

Value  =  Σ ( digit × baseposition )
Every positional number system works this way — each digit is worth its face value times the base raised to its column position, counting from 0 on the right.
Decimal 13  =  (1×23) + (1×22) + (0×21) + (1×20)  =  Binary 1101
Reading the same identity in reverse: each binary digit's column is worth a power of 2, and summing the ones that are "1" gives back the decimal value.

Why hex exists at all

Hardware only ever stores binary — every register, address, and byte is fundamentally a string of 1s and 0s. The problem is readability: a 16-bit value in binary is sixteen characters of 1s and 0s, easy to mistype and hard to eyeball. Hex solves this because 16 is a power of 2 (24), so exactly 4 binary bits map to exactly 1 hex digit, with no remainder and no rounding. That's the entire reason hex is used everywhere in electronics and programming — memory addresses, color codes, MAC addresses — it's not a different kind of number, just a 4x-shorter way of writing the same bits. Octal does the same job at 3 bits per digit, which is why it shows up in older Unix file permissions but has mostly been superseded by hex.

Binary → HexGroup bits into 4s from the right, convert each group to one hex digit: 1101 1010 → D, A → 0xDA.
Binary → OctalGroup bits into 3s from the right, convert each group to one octal digit: 011 010 → 3, 2 → 032.

Converting decimal to another base

Going the other direction — decimal into binary, octal, or hex — uses repeated division: divide by the target base, record the remainder, and keep dividing the quotient until it reaches zero. Reading the remainders from last to first gives the converted number. For decimal 13 into binary: 13÷2 = 6 remainder 1, 6÷2 = 3 remainder 0, 3÷2 = 1 remainder 1, 1÷2 = 0 remainder 1 — read bottom to top, that's 1101. The same procedure works for any target base; only the divisor changes.

Common terms, decoded

TermMeaning
Base (radix)The number of distinct digits a system uses before carrying to a new column
BitA single binary digit — either 0 or 1
Nibble4 bits — exactly the amount needed to represent one hex digit
Byte8 bits — commonly written as exactly two hex digits, e.g. 0xFF
0x / 0b prefixCommon notation marking a literal as hexadecimal (0x) or binary (0b) in code, so it isn't misread as decimal

Key takeaways

  • ✓A base is just how many digits exist before carrying — the value being represented never changes between bases, only how it's written.
  • ✓Binary is what hardware actually stores; hex and octal are purely human-readable shorthand for the same bits.
  • ✓Hex maps 4 bits to 1 digit exactly, with no remainder — that's why it's the standard shorthand rather than an arbitrary choice.
  • ✓Converting binary to hex or octal is grouping and lookup, not division; converting decimal to another base uses repeated division and remainders.
  • ✓Always check the base a number is written in before reading it — "10" means two in binary, eight in octal, and sixteen in hex.

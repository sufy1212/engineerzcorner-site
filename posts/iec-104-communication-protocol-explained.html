IEC 104 Communication Protocol Explained

IEC 60870-5-104 is the protocol that lets a control center talk to substations and remote sites over an ordinary IP network — same data model as its serial predecessor, but no longer limited by a wire.

What IEC 104 actually does

IEC 60870-5-104 is a telecontrol protocol built for Supervisory Control and Data Acquisition (SCADA) in remote control systems — think a utility control center monitoring and operating substations, pumping stations, or metering points spread across a wide area. It's an extension of the IEC 101 standard, carrying the same application-layer data (measurements, status points, commands) but running over TCP/IP (per RFC 793 and RFC 791) instead of a dedicated serial line. That single change is what lets it operate over routed networks, fiber, or even cellular links, at distances IEC 101's point-to-point serial connection was never designed for.

Protocol overview

Same data model as IEC 101, a different transport underneath it.

ASDU
Application service data unit
The application-layer data unit carrying the actual process content — measured values, status points, commands, and timestamps — identical in structure to IEC 101, which is what keeps the two standards closely related.
APCI
Application protocol control info
A frame-control header wrapped around each ASDU, handling sequence numbering and link-level control functions like starting/stopping data transfer and sending test frames to confirm the connection is alive.
Master-Slave Relationship
Control center & remote station roles
The control center acts as the master, initiating requests and issuing commands; the remote substation acts as the slave, responding to requests and reporting its own data — establishing which side drives the session.
General Interrogation
Full-station resync
A master-initiated "send me everything" request that pulls a complete, current snapshot of every monitored point — run at startup, or after a communication interruption, to rebuild a consistent picture rather than trusting an incremental catch-up.
Spontaneous Reporting
Event-driven data push
By default a substation pushes a changed value the moment it happens rather than only answering polls — keeping the master current in near real time while using far less bandwidth than continuous polling of every point.
Time Synchronization
Clock alignment across the link
Periodic time-sync messages keep the substation's clock aligned with the master, so timestamped events from different sites remain consistent — essential for reconstructing the correct sequence of events after a disturbance.

Communication sequence

1Control Center (master) opens a TCP connection to the remote station and sends an ASDU request, such as a general interrogation.
2Remote Substation (slave) responds with the requested data, or reports a change spontaneously as soon as a monitored value moves.
3Either side can then issue supervisory control commands or transfer files over the same established connection, without renegotiating the session.

Implementation & security checklist

  • 1Confirm the TCP/IP path and firewall rules between the control center and every remote station
  • 2Set appropriate timeout, interrogation, and time-sync intervals for the link
  • 3Verify redundant communication paths where the application requires high availability
  • 4Enable encryption, VPN/IPsec, or IEC 62351-compliant security rather than running the protocol in the clear
  • 5Test both spontaneous event reporting and a full general interrogation after any commissioning change
  • 6Confirm interoperability with any existing IEC 101, IEC 61850, or DNP3 systems on a mixed-protocol site
Because IEC 104 rides on a standard IP network, it's easy to treat the network itself as the security boundary — but the protocol wasn't originally designed with encryption built in, so that boundary has to be built deliberately, not assumed.

Key takeaways

  • ✓IEC 104 extends IEC 101 onto TCP/IP, keeping the same ASDU data structure while adding networked, effectively unlimited-distance communication.
  • ✓It uses a master-slave model, but isn't purely poll-driven — spontaneous reporting pushes changed values immediately without waiting for a poll.
  • ✓Riding on a standard IP network doesn't make it secure by default — encryption, VPN/IPsec, or IEC 62351 compliance need to be deliberately configured.
  • ✓Consistent time synchronization across stations is what makes sequence-of-events analysis meaningful after a disturbance, not just a housekeeping detail.

IEC 61850 Digital Substation Protocol Explained

IEC 61850 is what turned the substation relay room from a wall of copper terminal blocks into a network. Trip signals become GOOSE messages, CT/VT secondaries become a digitized sample stream, and a wiring diagram becomes a configuration file.

Engineerz CorneRReference · Electrical / Substation Automation
01
The standard defines three architecture levels — process, bay, and station — and most of what it changes happens at the process bus, where copper CT/VT wiring is replaced by a digitized sample stream.
02
GOOSE and Sampled Values are frequently confused but do different jobs: GOOSE carries discrete events (trips, status changes) between peer IEDs; Sampled Values carries a continuous stream of digitized waveform measurements.
03
Neither GOOSE nor Sampled Values has built-in authentication or encryption in their standard form — both are Layer 2 multicast, so anyone with access to the substation LAN can potentially inject or spoof messages.
04
An SCL (Substation Configuration Language) file describes an IED's full data model and capabilities in XML — what used to be a continuity check on a wiring diagram becomes a subscription/configuration check.

What IEC 61850 actually does

IEC 61850 is the international standard (from IEC Technical Committee 57) for communication networks and systems in electrical substations. Before it, protection relays, bay controllers, and SCADA systems from different manufacturers typically spoke different proprietary protocols, and the connections between CTs/VTs, protection relays, and circuit breakers were hardwired copper. IEC 61850 defines a common object-oriented data model — so a "circuit breaker" or "transformer" looks the same regardless of vendor — plus a set of communication services mapped onto Ethernet, which is what makes multi-vendor interoperability and a digital (rather than hardwired) substation possible.

Substation architecture: process, bay, station

Three functional levels, connected by a process bus and a station bus.

Process Level
Switchyard primary equipment
Circuit breakers, disconnectors, and instrument transformers, plus the merging units that digitize CT/VT secondaries into a sample stream — the layer where a digital substation's copper is replaced by fiber.
Bay Level
Protection & control IEDs
Protection relays and bay controllers (Intelligent Electronic Devices, or IEDs) subscribe to sampled values and each other's GOOSE messages to run protection logic and interlocking for one bay of the switchyard.
Station Level
SCADA / HMI / gateway
The station HMI, historian, and SCADA gateway — reading and writing bay-level data via MMS, and often presenting a single consistent IEC 61850 or IEC 60870-5-104 interface upstream to the control center.
Merging Unit
Analog-to-digital bridge
Connects to conventional or non-conventional CTs/VTs, digitizes the instantaneous current/voltage waveform at 80 or 256 samples per power cycle, and publishes it as a continuous Sampled Values multicast stream.
Process Bus
Merging units & IEDs, over fiber
The Ethernet network carrying Sampled Values and GOOSE between the process level and the bay level — the piece that physically replaces the CT/VT copper wiring run in a digital substation.
SCL File
Substation Configuration Language
An XML file describing an IED's data model and a substation's full logical connections between IEDs — engineered, version-controlled, and validated instead of traced out on a wiring diagram.

The three communication services

ServiceCarriesTransportTypical use
GOOSEDiscrete events — trips, status/position changes, interlockingLayer 2 Ethernet multicast, bypasses TCP/IP, sub-4ms deliveryPeer-to-peer protection & control between bay-level IEDs
Sampled Values (SV)Continuous digitized current/voltage waveform, 80–256 samples/cycleLayer 2 Ethernet multicast, bypasses TCP/IPMerging unit → protection IED on the process bus
MMSReports, measurements, control commands, historical/config dataClient-server over TCP/IP, port 102Bay-level IED ↔ station-level SCADA/HMI
GOOSE and Sampled Values both run directly on Ethernet rather than TCP/IP — skipping the handshaking and retransmission overhead of a full network stack is exactly what makes their tight timing budgets achievable, but it also means they don't inherit the IP layer's routing or built-in security options.

How a trip actually travels

1A merging unit at the process level digitizes the CT/VT waveform and publishes it as a continuous Sampled Values stream on the process bus.
2A protection IED at the bay level subscribes to that stream, runs its protection algorithm on the digitized waveform, and detects a fault condition.
3The protection IED publishes a GOOSE trip message; a circuit breaker IED subscribed to it acts on the command, typically within a few milliseconds.
4The event and updated status are also reported up to the station-level SCADA/HMI via MMS, and onward to the control center — often over IEC 60870-5-104 or IEC 61850-90-5 for the wide-area link.

Implementation & commissioning checklist

  • 1Verify the SCL configuration file matches the IEDs actually installed and their firmware/Edition (1 vs 2) capability
  • 2End-to-end test GOOSE trip timing from publishing IED to subscribing breaker, not just each device in isolation
  • 3Confirm time synchronization (PTP per IEC 61850-9-3, or equivalent) is stable across every IED sharing sampled values
  • 4Check multi-vendor interoperability explicitly — a shared standard doesn't guarantee every vendor implemented every optional feature the same way
  • 5Apply VLAN segmentation and priority tagging to the process/station bus rather than running everything on a flat network
  • 6Confirm whether a redundancy protocol (PRP or HSR) is in use and test actual failover, not just its configuration
  • 7Review the site's philosophy on backup hardwired trip paths — many digital substations still keep one as a fallback

Key takeaways

  • ✓IEC 61850 replaces hardwired substation panels with a common data model and Ethernet-based communication, enabling true multi-vendor interoperability.
  • ✓GOOSE (events) and Sampled Values (continuous waveform) are distinct services with different jobs — don't treat them as interchangeable.
  • ✓Sub-4ms GOOSE delivery comes from bypassing TCP/IP entirely, which is also why it doesn't inherit IP-level security by default.
  • ✓An SCL configuration file is now as safety-critical as a wiring diagram once was — commissioning has to validate it with the same rigor.
